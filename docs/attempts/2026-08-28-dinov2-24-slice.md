## 1. The finding that matters most

**`KneeNet`'s input normalisation does not travel in the checkpoint, and every
scoring site was silently dropping it.**

`src/model/net.py:182` registers `input_mean` / `input_std` with
`persistent=False`. They are therefore absent from the state dict, and each
construction site has to supply them itself. Training does, through
`net.backbone_defaults(BACKBONE)` -> the Lightning module. Two other sites did
not:

- notebook 08's per-finding scoring cell (`scoring_model = net.KneeNet(...)`)
- notebook 10's tuned load (`model = net.KneeNet(backbone, num_features)`)

Verified locally:

    input_mean in state_dict: False
    strict load into the un-normalised model: OK   <- no error
    scored.input_mean is None
    identical predictions: False

The strict load succeeds. No missing key, no shape error. A ViT trained on
ImageNet-normalised input is scored on raw uint8 and simply reads as a worse
checkpoint. **ConvNeXt is immune** -- `backbone_defaults` returns `None` for
it -- which is why this survived every ConvNeXt run on the project.

**This is the leading explanation for the 0.823 / 0.864 discrepancy.** The
24-slice DINOv2 run logged gold 0.864 at its last epoch from the in-memory
model; the scoring cell, reloading the same weights, printed macro 0.823. Not
proven to account for the whole -0.041 (a random-weight ViT is insensitive, so
the local reproduction shows the mechanism, not the magnitude), but it is a
certain bug at that exact site.

Fixed at all three sites; both notebooks now print `input normalisation: on`.
`tests/test_backbone_normalisation.py` guards it.

## 2. Still open, deliberately not fixed

> **Closed 2026-08-28**, later the same day, when `docs/plan.md` was replaced.
> The series-selection mismatch below is fixed: notebook 10 has `pick_series`,
> applying the same `np.linspace` rule `StudyIndex.series_for` uses, guarded
> by `tests/test_notebook.py::TestTrainingAndSubmissionAgree`. It moved with
> the rest of P0 rather than alone, so no LB reference was protected by
> leaving it — the DINOv2 run it was being held for was never submitted, and
> that axis is now closed.

**Series selection diverges between training and submission.** Training
(`src/model/dataset.py:168`) spreads its pick with `np.linspace`; notebook 10's
`tuned_predict` takes `volumes[:TUNED_MAX_SERIES]`, a head truncation. For a
7-series study that is positions `[0,2,3,4,6]` against `[0,1,2,3,4]`. Series
ordering matches (both sort by SeriesInstanceUID), so the difference is purely
linspace-vs-head, and it hits **32.5% of studies**.

Left alone because changing it moves submission semantics against the existing
LB references. For a first DINOv2 submission there is no reference to protect
and matching training is simply correct -- one line, in `tuned_predict`.

## 3. Measurements taken this session

### DINOv2-S fine-tune probe, fold 1, 16 x 5

Macro gold **0.820** against the plan's gate on 0.861:

- `>= 0.861` axis open; `0.851-0.861` diversity member; **`< 0.85` closed**

0.820 is 0.030 below the bottom band. The fine-tune itself worked -- +0.050
over frozen DINOv2's 0.770, close to the +0.058 fine-tuning bought ConvNeXt --
so the trunk is weaker on this task, not broken. Three findings went *backwards*
against its own frozen self: Lateral OA 0.820 vs 0.899, Lateral Meniscus 0.621
vs 0.680, PF OA 0.736 vs 0.772.

### DINOv2-S at 24 slices, 20 epochs, fold 1

    epoch   1     5     7     9(sel) 10    14    16    18    20
    val   0.711 0.840 0.846 0.860  0.856 0.853 0.847 0.844 0.843
    gold  0.674 0.826 0.834 0.849  0.869 0.865 0.867 0.864 0.864

- **Val selection cost 0.015** (selected 0.849 against a converged ~0.864),
  the worst on this project; 0.012 in the fold-1 reference, 0.002 at 8 slices.
- **Val and gold diverge for eleven straight epochs**: val falls 0.860 -> 0.843
  while gold holds flat at ~0.864. Val is agreement with *mined* labels; gold
  is agreement with radiologists. Consistent with late training fitting label
  noise, which would make val a biased selector rather than a noisy one. 58
  studies cannot establish it.
- **`EPOCHS = 20` restretched OneCycleLR** (`pct_start` 0.3, default): the LR
  peaks near epoch 6 of 20 against 3.6 of 12. Epoch indices in this run are
  **not comparable** to any earlier run.
- Converged gold ~0.864 against the reference 0.861 and the banked best 0.865
  -- level, at a run-to-run sd of ~0.004.

### Checkpoint selection hazard

Notebook 08's scoring cell falls back to `sorted(glob("lit_fold{N}*.ckpt"))[0]`
-- first *alphabetically*, and `-` (45) < `.` (46) < `_` (95). So
`lit_fold1-v1.ckpt` beats `lit_fold1.ckpt` beats `lit_fold1_old.ckpt`, and
Lightning writes `-vN` on every name collision.
